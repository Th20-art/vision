BILAN — 8 optimisations appliquées directement dans les fichiers :

[background.js]
  - Extraction d'un helper claudeCall(apiKey, { model, system, messages, tools, maxTokens })
    Les 3 handlers (ANALYZE_PRODUCT, ANALYZE_MEDIA, RESEARCH_SUBJECT) dupliquaient
    les memes headers et la meme structure fetch (~25 lignes en double supprimees).
    Desormais un seul point de modification si le header ou le endpoint change.

[popup.js]
  - Fix de checkTab : forEach imbriques -> Array.find / Array.some
    L'ancien code parcourait toutes les iterations meme apres avoir trouve un match
    (forEach ne supporte pas break). find/some s'arretent au premier resultat.
  - DocumentFragment dans renderInterceptions (30 items max)
    Les noeuds DOM etaient appended un par un au parent (un reflow par item).
    Desormais construits hors-DOM puis inseres en une seule operation.
  - DocumentFragment dans renderQStats (5 items max)
    Meme correction que renderInterceptions.

[content.js]
  - NATIVE_SELECTORS (13 selecteurs CSS) deplace en scope module
    Ce tableau etait recree a chaque appel de detectCollabs, declenchee
    sur chaque mutation DOM sur TikTok (scroll, swipe de video).
  - 6 regex de getSmartAlts deplacees en scope module
    (RE_SUPERMARKET, RE_BEAUTY, RE_ELECTRONICS, RE_TOY, RE_FASHION, RE_BOOK)
    Recompilees a chaque appel auparavant. Allouees une seule fois au chargement.
  - DocumentFragment dans renderAnalysis (boucle signaux, 3 items max)
    Meme logique que popup.js.
  - DocumentFragment dans openIntercept (boucle conflits ambitions standard + custom)
    Boucles standard et custom regroupees dans un fragment unique.
  - updateGoalBanner : suppression de 2 document.getElementById repetes
    pgoalIco est maintenant reference dans EL.pGoalIco a la construction (buildOverlay).
    La ligne lbl.textContent = "TON OBJECTIF" qui reecrivait la valeur deja
    initialisee dans buildOverlay a ete supprimee (doublon inutile).

BILAN — 15 ameliorations appliquees dans content.js (DARK_PATTERN_DETECTORS) :

[3 nouveaux detecteurs ajoutés]
  - Roach motel (severity: high)
    Détecte les offres faciles à souscrire mais difficiles à annuler :
    résiliation par téléphone/courrier, tacite reconduction, engagement minimum,
    résiliation impossible. 15 patterns (FR + EN).
  - Privacy Zuckering (severity: high)
    Cases à cocher présélectionnées pour partager des données avec des partenaires
    tiers (marketing, profilage, ciblage). Distinct de "Case pré-cochée" (payant).
  - Radio piège (severity: high)
    Bouton radio présélectionné sur l'option annuelle ou premium dans un contexte
    de plan tarifaire (classes plan/pricing/subscription/tarif/forfait/pack).

[Champ severity ajouté aux 12 detecteurs existants]
  high   : Case pré-cochée, Ajout forcé au panier, Abonnement caché, Coûts cachés
  medium : Faux compteur de stock, Minuterie d'urgence, Confirmshaming,
           Pop-up de rétention, Fausse preuve sociale, Bouton piège visuel,
           Prix barré suspect
  low    : Ancrage de prix
  → utilisé dans patrolPage pour l'épaisseur du contour : 3px/2px/1px

[Detecteurs renforcés]
  - Prix barré suspect : detection du % affiché gonflé par rapport au % reel calculé.
    Si le texte affiche "-X%" mais que la difference de prix ne correspond pas
    (écart > 10pts), le message mentionne les deux chiffres.
  - Abonnement caché : +5 patterns (tacite reconduction, reconduit automatiquement,
    résiliation à/avant la fin, "puis X€/mois", "then $X/month").
  - Coûts cachés : suppression de la restriction URL-only. Hors checkout, les
    patterns clairement abusifs (surcharge, mandatory fee, convenience fee,
    activation fee, frais obligatoire) sont toujours signalés.
    Sur checkout : 4 patterns supplémentaires (frais de réservation, convenience fee,
    frais de dossier, activation fee).
  - Bouton piège visuel : remplacement du test "texte gris" par un vrai calcul
    de contraste WCAG (luminance relative sRGB). Seuil : ratio < 3.0:1
    (norme WCAG 2.1 niveau AA pour les composants UI). Le message affiche
    le ratio calculé. Fallback sur l'ancien test si backgroundColor non lisible.

DEMANDE 5 : "youtube fonctionne toujours pas" — Fix robustesse YouTube SPA
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[content.js — guardOverlayOnSPA()]
  - Ajout d'un setInterval fallback toutes les 2s : filet de sécurité
    si les événements MutationObserver / YouTube SPA ne tirent pas.
  - Observer document.documentElement (pas seulement body) pour détecter
    si <body> lui-même est remplacé lors d'une navigation YouTube extreme.
  - Re-observe le nouveau body si document.body change entre deux appels.
  - Nouveaux listeners : yt-navigate-start, popstate (en plus de
    yt-navigate-finish et yt-page-data-updated déjà présents).

[content.js — buildOverlay()]
  - Styles critiques inlinés directement sur #mrr-avatar-wrap et #mrr-root
    (position:fixed, z-index, display:flex) → persistance visuelle même si
    l'injection du <style> est bloquée par un CSP strict (ex : YouTube).
  - Injection CSS dans un try/catch avec log d'avertissement si bloqué.
  - Vérification document.head avant appendChild (évite crash null).
  - console.log("[Miroir] buildOverlay() démarré") et confirmation
    d'injection pour faciliter le diagnostic dans la console DevTools.

[content.js — init()]
  - Retry automatique si document.body est null au moment du callback
    chrome.storage.local (setTimeout 500ms) — cas rare YouTube SPA.
